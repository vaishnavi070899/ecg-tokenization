Discrete Tokenization of ECG Signals via Residual Vector Quantization

View Code on GitHub vgg2023@nyu.edu
Vaishnavi Gupta NYU Tandon School of Engineering ECG as Language Project Aug 2026
We investigate whether ECG time-series can be tokenized into a discrete vocabulary suitable for downstream arrhythmia classification and generative modeling. The central obstacle is codebook collapse. Across sixteen experiments on PTB-XL (21,799 ECGs), we show collapse in multi-stage RVQ has three distinct causes — early training instability, a data-driven capacity ceiling of ~120 active codes per encoder stage, and stage hierarchy mismatch — and that standard regularization approaches address only the first. The architectural solution combines stage-specific codebook sizing K=[256,256,128,64], k-means++ warm-start initialization, and a Non-Stationary VQ neighbor update, achieving 97.7% codebook utilization and MSE=0.0058 on PTB-XL — the first configuration to simultaneously satisfy all three viability criteria.
Why VQ-VAE — Why ECG Before EEG
Why VQ-VAE for ECG Tokenization

VQ-VAE is the canonical architecture for learning discrete, reusable representations from continuous signals. It replaces the continuous latent space of a standard VAE with a learned codebook — a finite vocabulary of prototypical patterns. For ECG signals, this is exactly the right framing: a cardiologist reading a rhythm strip is not doing regression over a continuous signal, they are recognizing discrete morphological patterns — P waves, QRS complexes, ST deviations — and applying them diagnostically. VQ-VAE learns that vocabulary from data.

The alternative discrete approaches — patch-based tokenization, fixed scalar quantization, masked reconstruction — either lack learned vocabularies, sacrifice adaptive alignment, or do not produce reusable token indices suitable for autoregressive modeling. VQ-VAE's token indices are directly analogous to word indices in a text vocabulary, making downstream sequence modeling straightforward.

The precedent from audio is strong: SoundStream and EnCodec both use Residual VQ-VAE as their tokenization backbone, and both produce discrete token sequences that support downstream generation. The structural analogy to ECG is direct — both are continuous time-series signals with repeating structural units.

Why ECG Before EEG

ECG signals have a well-defined, repeating unit structure — the PQRST complex — with known clinical meaning at each component. A single cardiac cycle is approximately 0.6–1.0 seconds, and its morphology is consistent enough across patients that clinicians use the same vocabulary to describe it globally. This makes ECG an ideal proving ground for discrete tokenization: if a learned codebook can capture clinically meaningful structure in a signal with known ground truth morphology, the methodology can later be extended to EEG.

EEG, by contrast, is higher-dimensional (64+ channels vs 12), noisier, lacks a repeating structural unit analogous to PQRST, and does not have the same rich public labeling infrastructure. Starting with ECG is a deliberate scaffolding decision — validate the tokenization framework on a tractable signal first, then transfer to the target domain. This follows the same logic SoundStream applied to audio before extending to noisier real-world acoustic environments.

Loss Function

Reconstruction loss — MSE between input and reconstructed ECG. Forces tokens to preserve signal structure.

Codebook loss — pushes codebook vectors toward encoder outputs.

Commitment loss (β=0.25) — pushes encoder outputs toward codebook vectors, preventing encoder drift.

Straight-through estimator — passes gradients through the non-differentiable argmin step during backpropagation. Codebook updates via EMA, not gradient descent.

Metrics Guide

No single metric tells the full story. All three must be interpreted jointly — each one reveals a different dimension of codebook health, and the interaction between them is what exposes what the model is actually doing.

Mean MSE — Reconstruction Quality

Mean MSE measures the average squared difference between the original ECG signal and its reconstruction after passing through encoder → codebook → decoder. It is the most intuitive metric: lower means the signal came back more accurately.

MSE is the easiest metric to improve and the most dangerous to optimize in isolation. A model can achieve low MSE by collapsing onto just 20–30 dominant codes and reconstructing everything with those — this is exactly what happened at K=1024 in Exp 1, where MSE=0.0876 looked like progress while 87.5% of the codebook was dead. Low MSE is necessary but not sufficient for a healthy model. It must always be read alongside utilization and diversity.

Target: MSE < 0.009. Final architecture: MSE = 0.0058.
Dead Code % — Codebook Utilization

Dead code % is the fraction of codebook entries that receive zero assignments — entries the encoder never maps to during training. A dead code is permanently excluded from the learned vocabulary. The model has effectively decided that region of the codebook space is not useful, and because EMA updates are driven by assignments, codes that never win assignments never get updated — they stay dead indefinitely.

We want dead code % to be as low as possible. High dead code % is the primary signal of codebook collapse. But there is a critical subtlety: a high activation count — many codes used at least once — does not mean the codebook is healthy. A code that activates twice per epoch while another activates 10,000 times is functionally almost dead. This is why dead code % alone is not enough — we also need perplexity to capture how evenly usage is distributed.

Target: Dead code % < 5%. Final architecture Stage 4: 1.6% dead. Stage 2 structural ceiling: ~22% (signal property, not optimization failure).
Perplexity — Representational Diversity

Perplexity is the exponentiated Shannon entropy of the code usage distribution. Concretely: if you track what fraction of assignments goes to each codebook entry, perplexity measures how evenly spread that distribution is.

Perplexity = 1 means a single code wins every assignment. Perplexity = K means every code is used equally — perfectly uniform distribution. In practice, healthy models land somewhere in between, but far from 1.

Perplexity is the most honest metric in the project. It captures not just whether codes are used, but how evenly — and it consistently exposed the limits of every intervention before the other metrics did. In Exp 4, data scaling improved MSE significantly but perplexity held flat at 0.65–0.70 normalized across all dataset sizes, proving that more data was not helping the codebook become more expressive.

Target: Aggregate perplexity > 355 (single-stage baseline at γ=0.95). Final architecture aggregate: 627.6 (sum across all 4 stages).

Experimental Methodology

Experiments are designed to address one variable at a time, building on each result to inform the next. Decisions are never made on a single metric — each experiment is evaluated across MSE, active codes, dead code %, and perplexity simultaneously. All experiments run locally on a laptop without GPU access. Data is PTB-XL (21,799 records, Lead I, 100Hz, z-score normalized).

Experiment Decision Flowchart

Each experiment was motivated by a specific finding from the previous one. This chain shows what each result revealed, what correction it suggested, and what that correction actually produced.

Phase 1 — Establishing the Baseline Problem
Exp 1 Codebook Size Sweep (K=64 → 1024, no reset)
Finding: Active codes plateau at ~100–130 regardless of K. At K=1024, 87.5% of the codebook is permanently dead. Larger codebooks reconstruct marginally better but collapse harder — 128 dead codes at K=64, 896 dead codes at K=1024.
What this suggests: The problem is not insufficient capacity. The model is converging to a small stable set of codes early in training and never exploring the rest. Two possible fixes: (1) force the dead codes back to life through reinitialization, or (2) reduce EMA decay so the codebook adapts faster and does not lock in early winners.
Next: Exp 2 — test three reset strategies to see if dead codes can be revived.
collapse confirmed → try reset
Exp 2 Codebook Reset Strategies (Random Restart, K-Means, Anchor)
Finding: All three reset strategies dramatically improved reconstruction (MSE dropped 35–45%). Active codes jumped from 96 to 343–395. But perplexity stayed highly skewed — usage distribution remained power-law. Reset revived dead codes but did not change the dynamics that killed them.
What this suggests: Reset is reactive, not preventative. The model still collapses toward the same dominant codes — it just gets nudged back periodically. K-Means Centroid Reset gives the best diversity (highest perplexity). The underlying objective still has no incentive to use all codes. Two open questions: (1) does EMA decay speed matter? (2) does the codebook size itself matter?
Next: Exp 12 — test reset at extreme K values to understand the capacity-utilization tradeoff. Exp 3 — tune EMA decay.
reset helps but does not solve → test boundaries
Exp 12 Reset at K=128 and K=1024
Finding: K=128 achieved 96.1% utilization — near-complete — but MSE=0.0760, worse than K=512. K=1024 had best MSE (0.0448) but visual inspection showed QRS peaks not reconstructed to scale — suspected overfitting. Low MSE is not evidence of a good model.
What this suggests: The codebook may simply be too large for the signal. K=128 forces utilization by leaving no room for dead codes. The signal might only naturally support ~120 separable patterns at this encoder resolution. K=512 is over-capacity. A hypothesis to test later: maybe the right answer is a smaller K, not a better reset strategy.
Next: Exp 3 — tune EMA decay as a training dynamics fix before concluding the problem is architectural.
capacity ceiling hypothesis → tune training dynamics
Phase 2 — Ruling Out Simpler Explanations
Exp 3 EMA Decay Rate Sweep (γ = 0.90, 0.95, 0.99)
Finding: EMA decay modulates collapse severity but does not eliminate it. γ=0.95 gives the best reconstruction (MSE=0.0500) with stable codebook dynamics. γ=0.99 is slow and stable but worse reconstruction. γ=0.90 is fast but noisy — fluctuating assignments. All three still show 23–27% dead codes.
What this suggests: EMA tuning is a dial, not a fix. The collapse ceiling persists regardless of decay speed. The next question: is this collapse driven by not enough data? If the model saw more diverse signals, would it naturally use more codes?
Decision: γ=0.95 fixed for all subsequent experiments. Next: Exp 4 — scale dataset from 1k to 10k to test whether data starvation is causing collapse.
EMA not the fix → is it a data problem?
Exp 4 Data Scaling (1k → 2k → 5k → 10k records)
Finding: Reconstruction improved monotonically with data — MSE dropped from 0.0500 (1k) to 0.0354 (10k). But dead code % held flat at 21–29% across all dataset sizes. The model did not use more of its vocabulary when given more data.
What this suggests: Collapse is not a data starvation problem. It is an objective misalignment problem — the model has no incentive to use all codes. The loss function optimizes reconstruction, not diversity. This is the decisive ruling-out: more data helps MSE, not utilization. The fix must be architectural or objective-level.
Next: Exp 5 — try Residual VQ to distribute the representational burden across multiple codebooks, both improving reconstruction and potentially reducing per-stage collapse.
not data → try multi-stage architecture
Exp 5 Residual Vector Quantization — 2/3/4 layers + K sweep
Finding: RVQ-4 at K=512 achieved MSE=0.0063 — an 87% improvement over single-stage VQ. Each stage captures what the previous missed. But dead codes persisted at 22–32% across all depths — distributed across stages, not eliminated. K=128 per stage hit ~94–95% utilization, revealing that ~120 active codes is the natural ceiling per stage at this encoder resolution. K=256 was the best tradeoff: 82–88% utilization with competitive MSE.
What this suggests: RVQ is the right structural choice for reconstruction. The capacity ceiling (~120 active codes/stage) is a real property of the signal, not a training artifact. The collapse persisting at K=512 means the codebook has 4× more entries than the signal can fill. Logical next step: try objective-level fixes — entropy regularization, usage penalties, soft assignments — to force the model to distribute assignments more evenly.
Next: Exp 13, 14, 15 — regularization approaches targeting objective misalignment.
RVQ adopted → try regularization to fix remaining collapse
Phase 3 — Why Regularization Fails
Exp 13 Entropy Regularization (λ = 0.01, 0.1)
Finding: Entropy regularization made reconstruction worse — MSE rose to 0.0106–0.0123 vs 0.0063 baseline. At λ=0.1, entropy term contributed ~100× the reconstruction loss by mid-training, causing VQ loss to climb monotonically. Active codes barely improved (barely 1–2% reduction in dead %).
Why it failed: Entropy acts on soft assignment probabilities through the encoder. But codebook updates use hard argmin. A dead code that never wins a hard assignment receives no EMA update regardless of its soft probability — entropy cannot reach dead codes by design. The soft and hard assignment geometries are incompatible.
Verdict: Failed. Mechanism mismatch — cannot revive dead codes through soft signals when updates are hard. Next: try penalizing overused codes directly.
entropy fails → try direct usage penalty
Exp 14 Usage Penalty / Frequency Balancing (α = 0.01 → 1.0)
Finding: More stable than entropy reg — MSE held at 0.0065–0.0089. Perplexity improved slightly. But dead code % changed by only 1–3 percentage points across all α values. α=0.1 and α=1.0 differed by only 2 active codes at Stage 4.
Why it failed: Usage penalties discourage dominant codes but do not explicitly activate dead ones. The model redistributed assignments among already-active codes rather than exploring dead regions. Dead codes are not merely unpopular — they are unreachable given the encoder geometry. Penalizing the popular codes does not change where the encoder maps its outputs.
Verdict: Marginal, not sufficient. Redistributes active codes only. Does not expand into dead regions. Next: try soft assignments to smooth early-training dynamics before codes lock in.
usage penalty insufficient → try soft assignments
Exp 15 Temperature / Soft Assignments (T = 0.1 → 2.0)
Finding: Catastrophic failure at all temperatures in multi-stage RVQ. Low T (0.1, 0.5): Stage 1 healthy, Stages 2–4 collapsed to 86–95% dead — soft Stage 1 absorbed too much signal, leaving near-zero residuals for downstream stages. High T (1.0, 2.0): everything collapsed, MSE=0.0656–0.0758. One earlier implementation hit perplexity=1 with a single active code.
Why it failed: Soft assignments are fundamentally incompatible with EMA-based multi-stage RVQ. Stage boundaries require hard commitments — each stage needs a clean residual to work with. When Stage 1 uses soft assignments, it captures everything, leaving nothing meaningful for Stages 2–4.
Verdict: Failed completely. All three regularization approaches failed for the same underlying reason — they treat collapse as a distributional problem in the loss landscape. The binding constraint is structural: the capacity ceiling and stage hierarchy cannot be regularized away. The solution must come from the architecture.
all regularization failed → architecture is the only fix
Phase 4 — Architectural Resolution
Exp 16 NS-VQ + Warm-Start + Stage-Specific K=[256,256,128,64]
Finding: First configuration to satisfy all three viability criteria simultaneously. Stage 4: 63/64 active codes (1.6% dead). Full stack MSE=0.0058 — matching pre-NS-VQ baseline while using 31% fewer codebook entries. Stage 2 remained at ~22% dead — confirmed structural, not optimization failure.
Why it worked: Three problems required three separate fixes. (1) Warm-start (k-means++) addresses early training instability — codebook geometry is aligned to the data before any EMA updates occur. (2) NS-VQ neighbor update addresses gradient starvation — nearby unused codes receive decayed updates when a winner is selected. (3) Stage-specific K addresses hierarchy mismatch — K is matched to what each stage's residuals can actually support, rather than forcing uniform capacity.
Verdict: Success. First config meeting all criteria. Phase 1 complete. Next: Exp 6 — optimize latent dimension D independently, then Phase 2 begins.
architecture works → optimize remaining hyperparameter
Exp 6 Latent Dimension D Sweep (32, 64, 128)
Finding: D=64 optimal — best reconstruction (MSE=0.0056, val loss=0.005178). D=128 degraded both MSE and utilization despite larger capacity — Stage 2 dead codes rose to 27%. D=32 was surprisingly competitive (MSE=0.0059), suggesting ECG morphology lies on a low-dimensional latent manifold.
Why D=128 failed: Larger embedding dimensions expand the residual search space, making quantization harder for fixed-size codebooks. Quantization efficiency — not encoder expressivity — becomes the bottleneck at high D. The encoder can represent more with D=128, but the codebook cannot reliably partition the larger space.
Decision: D=64 fixed as final embedding dimension. Phase 1 architecture is fully determined. All components locked: RVQ-4, K=[256,256,128,64], D=64, γ=0.95, k-means++ warm-start, K-Means reset, hard assignments, NS-VQ update.
The thread across all 16 experiments: Exp 1 revealed collapse. Exp 2 and 12 showed reset helps but does not solve it. Exp 3 and 4 ruled out EMA and data as root causes. Exp 5 established RVQ as the architecture. Exp 13–15 proved regularization cannot fix structural collapse. Exp 16 resolved all three failure modes through architecture. Exp 6 finalized the last hyperparameter. Every experiment's result directly caused the next one to exist.

Results & Observations — The Full Story
Reconstruction Quality (MSE)

Reconstruction is the easiest metric to improve and the most dangerous to optimize in isolation. Every intervention that dramatically lowered MSE — K=1024 at 0.0448, Anchor Resampling at 0.0555 — came with severe utilization penalties. The clearest reconstruction gains came from: reset strategies (35–45% drop vs baseline), data scaling (monotonic improvement 1k→10k), and most significantly, RVQ depth (63% drop from single-stage to RVQ-2). The final configuration (Full Stack, Exp 16) achieves MSE=0.0058 — the best across all experiments — while using 31% fewer codebook entries than the best uniform-K baseline.

Codebook Utilization (Active Codes / Dead %)

Utilization tells the story of how honestly the model learned. From the 87.5% dead codes at K=1024 in Exp 1, to 1.6% at Stage 4 in the final Full Stack configuration — the path was not linear. Reset strategies helped but left power-law distributions. Regularization (Exp 13–15) failed to move the needle for structural reasons. The decisive improvement came from matching codebook capacity to the signal's intrinsic granularity: K=128 saturating at ~120 active codes per stage revealed that number as the natural ceiling at this encoder resolution. Stage-specific K=[256,256,128,64] works with that ceiling rather than against it.

Representational Diversity (Perplexity)

Perplexity consistently exposed the limits of every intervention before the other metrics did. It remained flat through data scaling (0.65–0.70 normalized across all dataset sizes), declined with RVQ depth (Stage 1 of deeper models faces harder residuals), and failed to meaningfully improve under any regularization approach. The final full-stack aggregate perplexity of 627.6 (sum across stages) far exceeds the single-stage baseline of 355.0 — confirming genuine diversity gain from the multi-stage architecture.

The Three-Problem Reframing

The most important finding of Phase 1 is not a metric. Codebook collapse in ECG RVQ tokenization is not one problem. It is three:

Problem 1 — Training dynamics: EMA inertia, early code specialization, objective misalignment. Addressed by: K-Means reset, γ=0.95, warm-start initialization.

Problem 2 — Data capacity ceiling: The ECG signal supports ~120 separable patterns per stage at 80ms resolution. This is a property of the signal, not a failure. Addressed by: setting K below the per-stage ceiling.

Problem 3 — Stage hierarchy mismatch: Later RVQ stages quantize lower-complexity residuals. Forcing uniform K across stages creates artificial dead-code pressure. Addressed by: K=[256,256,128,64].

Interventions that failed (Exp 13–15) all treated collapse as a distributional problem in the loss landscape. The binding constraint is structural. No auxiliary loss changes how many distinct patterns ECG signals contain at this resolution.

Anticipated Questions for Prof. Kapila
Why VQ-VAE and not another tokenization method?
VQ-VAE is the canonical architecture for discrete representation learning from continuous signals. It produces integer token indices directly analogous to word indices in a text vocabulary, which is precisely what we need for downstream sequence modeling. The precedent from audio (SoundStream, EnCodec) is strong and the structural analogy to ECG is direct — both are continuous time-series with repeating structural units. Starting with VQ-VAE before surveying alternatives was the right call because it is the most studied approach and its failure modes are well-characterized in the literature. We know exactly what we're working with.

Alternative methods considered and why they were not chosen first:

Patch-based Tokenization — divides the ECG into fixed-length windows and treats each as a token. Simple and interpretable, but the tokens are not learned — they are arbitrary fixed segments with no guarantee that boundaries align with physiologically meaningful units like PQRST complexes. ECG morphology does not divide evenly into uniform patches. Most patches at 80ms resolution would look nearly identical (flat baseline), and the vocabulary is fixed rather than emergent from data. Used in vision transformers (ViT) where patch content varies richly — less appropriate for a 1D signal with a dominant repeating structure.

QRS-Segmented Tokenization — segments ECG by detected QRS complexes, mapping each beat to an embedding. Physiologically principled and used in HeartLang. The core problem: it requires a reliable QRS detector as a preprocessing step, making the tokenization pipeline dependent on a separate algorithm. Any QRS detection errors propagate into the token sequence. It also forces variable-length tokens (beats vary in duration), which complicates downstream sequence modeling. VQ-VAE avoids this by learning fixed-length tokens from data without any preprocessing.

Finite Scalar Quantization (FSQ) — replaces the learned codebook with fixed scalar quantization grids, entirely sidestepping codebook collapse. Elegant and used in recent vision work. The reason not to start here: FSQ sacrifices adaptive vocabulary alignment — the codebook entries are not learned from the data, so they cannot align with the signal's natural cluster structure. For ECG, where the goal is to discover what the meaningful morphological primitives actually are, a fixed grid is the wrong prior. VQ-VAE's learned codebook is the scientific question, not just an implementation detail.

ST-MEM / Masked Signal Reconstruction — self-supervised approach that masks segments and trains the model to reconstruct them (analogous to BERT for ECG). Produces continuous embeddings, not discrete tokens. Does not generate a reusable vocabulary of integer indices. Cannot be fed directly into an autoregressive prior or language model without a separate discretization step. Good for pre-training representations but not the right architecture for the tokenization goal.

BEAT / Diffusion-based Tokenization — dual-level VQ with a bidirectional diffusion mechanism (HeartcareGPT, 2025). More complex architecture requiring substantially more compute and data. Starting with BEAT on a laptop with 1k records would have been the wrong order of operations — the complexity would have obscured which components were actually responsible for any failures. VQ-VAE's simplicity made the failure modes diagnosable.

The common thread: VQ-VAE was chosen because it is the right level of complexity for this stage of the project — learnable, interpretable, well-precedented, and diagnosable when it fails. The alternatives are either too rigid (patch, FSQ), too dependent on preprocessing (QRS-segmented), do not produce discrete tokens (ST-MEM), or too complex to debug at this scale (BEAT). The plan is to compare approaches once the VQ-VAE baseline is validated — not because VQ-VAE failed, but because comparing produces deeper understanding.
Why ECG and not EEG, given that EEG is the long-term goal?
ECG has a well-defined repeating unit — the PQRST complex — with known clinical meaning at each component. A single cardiac cycle is ~0.6–1.0 seconds, and its morphology is consistent enough across patients that clinicians use the same vocabulary globally. This makes ECG an ideal proving ground: if a learned codebook can capture clinically meaningful structure in a signal with known ground truth morphology, the methodology can transfer to EEG where the signal is higher-dimensional (64+ channels), noisier, lacks a repeating structural unit analogous to PQRST, and lacks PTB-XL's rich public labeling infrastructure. Starting with ECG is deliberate scaffolding — validate the tokenization framework on a tractable signal first, then extend to EEG. The framework itself is signal-agnostic.
Codebook collapse is still present after 16 experiments — did you actually solve it?
Partially, and the partial resolution is the scientific result. The final configuration achieves 97.7% codebook utilization (1.6% dead codes at Stage 4), which satisfies all three viability criteria simultaneously for the first time. But Stage 2 remains at ~22% dead — and this is structural, not a training failure. Stage 2 residuals simply do not contain enough intrinsic diversity to support K=256. This is not a bug; it is a finding about the signal's latent structure at this encoder resolution. The correct interpretation is that some dead-code behavior in later stages reflects genuine over-capacity — there are not 256 meaningfully different residual patterns to quantize at Stage 2. The paper's contribution is identifying this and showing why regularization cannot fix it.
Why did you choose K=512 as the initial codebook size?
At 100Hz, a 10-second ECG segment produces 1,000 samples. With 8× downsampling, each token represents ~80ms of signal — approximately one-tenth of a typical cardiac cycle. A single PQRST complex spans roughly 3–4 such tokens. K=512 was chosen as a reasonable upper bound on the number of morphologically distinct patterns one might expect at 80ms resolution, given the diversity of ECG morphologies across the PTB-XL dataset. It also follows the convention in audio codec literature (SoundStream uses K=1024). It turned out to be too large — the signal's intrinsic granularity is ~120 distinct patterns per stage — but that was not knowable before running the experiments.
Do these tokens actually mean anything clinically? How do you know they capture meaningful structure?
This is the open question that Phase 2 will answer. Phase 1 establishes that the tokenizer is healthy — active, diverse, and stable. Whether the tokens are semantically meaningful requires a downstream evaluation. The plan is a linear probe on PTB-XL diagnostic labels over frozen token sequences. If the probe performs competitively with a 1D ResNet trained directly on raw waveforms, the tokens carry clinically meaningful structure. If it does not, the codebook is compact but semantically empty. We do not yet know which it is. This is the honest answer, and it is the right next question.
What is the path to a downstream model?
Phase 2: Train a masked token prediction model on frozen token sequences from the Phase 1 tokenizer. Evaluate with a linear probe on PTB-XL superclass labels (Normal vs AFib vs ST-change etc.) — this determines whether the discrete representations carry clinically meaningful structure. Phase 3: If semantic validity is confirmed, train an autoregressive model over token sequences. The architecture decision (train from scratch vs fine-tune an existing LLM) is open and depends on Phase 2 results and available compute. The pacemaker application — generating physiologically realistic heartbeat signals — is a Phase 3 downstream use case, not an immediate deliverable.
All experiments used 1k records — is that enough to draw conclusions?
Exp 4 directly addresses this. Scaling from 1k to 10k records improved reconstruction consistently but left codebook utilization completely unchanged — dead codes held at 21–29% regardless of dataset size. This is a decisive negative result: the capacity ceiling is not a data scarcity artifact. It persists across a 10× increase in training records. For the architectural conclusions in Exp 16 and 6, 2k records were used with 30 epochs. The findings are consistent across all dataset sizes tested.
